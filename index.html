02

The loop

Read the machine. Then answer it.

Gcoolers is a governor, not a switch. It samples, decides, acts, and remembers — and every part of that loop is visible to you.

macmon reads the sensors; the governor weights CPU and GPU into one peak figure.

05

Meeting mode

Your Mac doesn't need to join the meeting.

Gcoolers watches for call apps by process activity. When it finds one it holds the fan ceiling at 42% and hands the previous behaviour back afterwards. It lowers the ceiling — it can't promise silence, and detection is a heuristic, so gcoolers meeting on pins it manually whenever you'd rather be certain.

08

Schedule · adaptive bias

A working day and a quiet night are different machines.

Turn the schedule on with gcoolers schedule on and the profile follows the clock. Quiet hours are separate and on by default — they nudge the whole curve later overnight even when no schedule is set.

Between 22:00 and 07:00 the curve engages 8°F later, tops out 4°F higher, drops the fan floor by 8 points, and slows sampling to at least 25 seconds.

Adaptive bias

It learns from results, not from your feelings about noise.

After each adjustment the governor compares the peak before and after. If the peak fell by at least 2°F the bias for that workload nudges up; if a fan above half speed bought nothing, it nudges down. Steps are 1.2% and the whole range is clamped.

-12%0+18%

  • gpu

One bias per workload shape, so a GPU render and a laptop on battery don't share a lesson.

It also remembers apps. Toggling meeting mode teaches it which app you were on, and a few heavy tools ship with a sensible default profile already — Xcode, Final Cut, Blender, Docker, and Cursor start on Cool.

10

Manifest

Your Mac. Your data.

Gcoolers needs one elevated privilege and takes nothing else. Here is the complete list of what it holds and why.

  1. 01

    Local

    No account, no telemetry, no network call.

    Sensors are read on your Mac and written to ~/Library/Application Support/Gcoolers. There is no server to send them to.

  2. 02

    No kernel extension

    User space, start to finish.

    Fan writes go through a small IOKit helper compiled from Tools/heatwatch-fan.c. Nothing is loaded into the kernel.

  3. 03

    One narrow privilege

    Passwordless sudo for the fan helper only.

    The sudoers rule names that single binary. It is written 440, validated with visudo, and removed again if validation fails.

  4. 04

    Built on your machine

    swiftc compiles the app locally.

    The menu bar app and widget are built from Sources/ during install rather than shipped as an opaque binary.

  5. 05

    MIT licensed

    Read it, fork it, audit it.

    The governor, the helper, the menu bar app, and the widget are all in one public repository.

11

Requirements

Apple Silicon, macOS 14 or newer.

Homebrew checks most of this for you. The one thing worth reading before you install is what happens on a Mac without fans.

Apple SiliconRequired
The Homebrew formula is arm64-only and the sensor reader is an arm64 build. Intel Macs are not supported.
macOS 14Or newer
The menu bar app and the widget are both built against a macOS 14 minimum.
FansIf your Mac has them
On a fanless Mac — MacBook Air, iPad-class silicon — there is nothing to spin. Monitoring, alerts, history, and export still work; fan control has no hardware to act on.
Python 3.10+Homebrew handles it
The governor is Python. Installing through Homebrew pulls python@3.12 as a dependency.
Xcode Command Line ToolsFor the app
swiftc compiles the menu bar app and widget on your machine. Without it the daemon and CLI still run.
Bundled helpersmacmon · heatwatch-fan
macmon reads the sensors. heatwatch-fan talks to the SMC and is compiled from Tools/heatwatch-fan.c during install.

Fanless Macs

On a MacBook Air there is nothing to spin — and Gcoolers won't pretend otherwise.

The governor still reads your sensors, still holds a profile, still detects calls, still keeps an hour of history, and still alerts you when the machine has been hot for ten minutes. What it cannot do is change a fan speed, because there is no fan. If cooler, quieter fans are the reason you're here, this is the row to check first.

What does gcoolers install change?

Four things, and nothing else. Every one of them is reversible by hand.

  1. /etc/sudoers.d/gcoolersOne sudoers rule

    A NOPASSWD entry for the fan helper alone — nothing else gets elevated. Gcoolers writes it with 440 permissions and validates it through visudo, removing it again if visudo rejects it. This is the one time you type your password.

  2. ~/Library/LaunchAgents/com.gcoolers.daemon.plistA user LaunchAgent

    Runs the governor at login and restarts it if it exits. A user agent, not a system daemon, and it logs to ~/Library/Logs/gcoolers.log.

  3. ~/Applications/Gcoolers.appThe menu bar app

    Compiled locally with swiftc from Sources/, so nothing arrives pre-built. The Notification Center widget ships inside it as GcoolersWidget.appex.

  4. ~/Library/Application Support/GcoolersLocal state only

    config.json, state.json, history.json, and learn.json. Temperatures, the active profile, and the adaptive bias live here and go nowhere else.

There is no uninstall subcommand yet. To remove it: unload the LaunchAgent, uninstall the formula, delete /etc/sudoers.d/gcoolers, then remove ~/Applications/Gcoolers.app and the support folder.

13 — Questions

The things people ask before installing.

What does Gcoolers actually change on my Mac?

Four things, all listed above: a sudoers rule scoped to the fan helper, a user LaunchAgent that keeps the governor running, a locally compiled Gcoolers.app in ~/Applications, and a state folder in ~/Library/Application Support. While it runs it sets fan targets through the SMC.

Does it modify macOS or firmware?

No. There is no kernel extension, no system daemon, and no firmware write. Fan targets are set through the SMC interface the same way Apple's own fan management does, and they are handed back when the governor stops.

Does it use a kernel extension?

No. The only privileged component is heatwatch-fan, a small user-space binary compiled from Tools/heatwatch-fan.c that talks to IOKit.

Which Macs are supported?

Apple Silicon Macs on macOS 14 or newer. The Homebrew formula requires arm64, and both the app and the widget are built against a macOS 14 minimum.

What happens on a fanless Mac?

Everything except fan control. Live CPU, GPU, and peak telemetry, profiles, meeting mode, schedules, alerts, history, and export all work. There are simply no fans for the governor to drive.

Does it run locally?

Yes. Nothing leaves the machine. There is no account, no analytics, and no network call in the governor — sensor samples are written to a local state folder and rotated out after an hour.

How does Meeting Mode work?

It watches for call apps by process activity — Zoom, FaceTime, and Webex count as soon as they are present; Discord, Teams, and Slack have to be doing work so a backgrounded app is not mistaken for a call. When one is detected the fan ceiling drops to 42% and the previous behaviour returns afterwards. It does not promise silence, and it is not a guarantee that a call was correctly detected.

Does it start automatically?

Yes, once you have run gcoolers install. The LaunchAgent starts the governor at login and restarts it if it exits.

What happens if Gcoolers stops?

The fans go back to macOS. Pausing releases them explicitly, and the helper restores automatic control rather than leaving a target pinned.

How do I remove it?

There is no uninstall subcommand yet — removal is four manual steps: launchctl unload ~/Library/LaunchAgents/com.gcoolers.daemon.plist, brew uninstall gcoolers, sudo rm /etc/sudoers.d/gcoolers, then delete ~/Applications/Gcoolers.app and ~/Library/Application Support/Gcoolers.

What information should I include in a support email?

Your Mac model, your macOS version, the Gcoolers version, the active profile, the full output of gcoolers doctor, and anything relevant from ~/Library/Logs/gcoolers.log.
